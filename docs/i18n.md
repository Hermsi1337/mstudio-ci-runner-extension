# Languages

User-facing text exists in English and German. Everything else in the repository is
English ([AGENTS.md](../AGENTS.md)).

## How the language is chosen

| Where | Source | Fallback |
|---|---|---|
| UI inside mStudio | `navigator.languages` of the browser (`src/i18n/react.tsx`) | `en` |
| Server functions | `x-locale` header, set by the client middleware from the same browser value; `Accept-Language` if missing (`src/middleware/error-handling.ts`) | `en` |

mStudio does not pass the user's language to the extension, so the browser language is
the closest signal. Only the language part of a tag counts: `de-AT` becomes `de`.

## Where texts live

| File | Content |
|---|---|
| `src/i18n/en.ts` | English catalog, source of truth for the key set |
| `src/i18n/de.ts` | German catalog, typed against the English one |
| `src/i18n/index.ts` | `resolveLocale`, `translate`, `translator` |
| `src/i18n/react.tsx` | `LocaleProvider`, `useTranslation`, `detectBrowserLocale` |

Keys are dotted and grouped by screen or concern: `form.*`, `runners.*`, `status.*`,
`error.*`. Placeholders use `{name}`.

## Errors

Server errors extend `PublicError` and carry a message key plus parameters instead of a
text. The error middleware renders the key in the language of the request and sends the
text to the client, which shows it as is. Adding an error means adding a key to both
catalogs and throwing the matching subclass (`NotFoundError`, `ProviderError`,
`UpstreamError`, `PermissionsInsufficientError`).

Zod validation messages from the generated request schemas stay English. They only
appear when a client bypasses the form; the form validates with localized rules first.

## Adding or changing text

1. Add the key to `src/i18n/en.ts` and `src/i18n/de.ts`.
2. Use it through `useTranslation()` in components or a `PublicError` subclass on the server.
3. `pnpm run test` checks that both catalogs have the same keys and placeholders.

Writing rules for both languages: [AGENTS.md](../AGENTS.md#writing-style).
